1. 설계 원칙
주제 단위 노출 : 질의 원문이 아닌 정규화된 주제(Topic)만 표기함
본문 비노출 : 타 사용자 답변 본문은 표시하지 않으며, 클릭 시 본인 권한으로 재질의함
근거 동반 : 모든 항목은 선정 근거(모수·증감)를 1줄로 함께 표기함
조건부 미노출 : 임계값 미달 블록은 제목·안내문구 포함 전체를 렌더링하지 않음
라벨 정합 : 폴백 단계에 따라 뱃지 문구가 함께 변경됨
2. 정보 구조
브리핑 카드 (brief-card)
├─ 헤더                  brief-header
├─ 블록 A. 나에게 관련    brief-block--personal    최대 2건
├─ 블록 B. 급상승 주제    brief-block--trending    최대 3건
├─ 블록 C. 많이 본 주제   brief-block--popular     최대 2건
└─ 푸터(안내 기준)        brief-footer
블록 순서 고정(A → B → C), 개인화 강도 높은 순으로 배치함
블록 단위로 노출·미노출이 독립 결정됨
3개 블록 전부 미달 시 brief-card 자체를 렌더링하지 않음
2.1 블록별 노출 조건
블록	노출 조건	미달 시
A. 나에게 관련	score ≥ 0.6 인 항목 1건 이상	블록 미노출
B. 급상승 주제	이번주 ≥ 10건 AND 증가율 ≥ 2.0 AND 고유사용자 ≥ 5명	블록 미노출
C. 많이 본 주제	7일 클러스터 ≥ 5건 AND 고유사용자 ≥ 3명	블록 미노출
3. 카드 헤더
3.1 구성
요소	내용	클래스
날짜	2026년 7월 23일 (목)	brief-date
타이틀	아침 브리핑	brief-title
서브	기획팀에서 이번 주 많이 확인한 주제입니다	brief-subtitle
접기	아이콘 버튼	brief-toggle
3.2 카피 규칙
헤더에 총 건수를 표기하지 않음 — 블록별 노출 개수와 불일치 발생
사용자 호칭·직급 미사용 — 홍길동 과장님 형태 금지
서브 문구는 블록 A 노출 여부에 따라 분기함
조건	서브 문구
블록 A 노출	최근 대화와 관련된 주제를 정리했습니다
블록 A 미노출	우리 부서에서 이번 주 많이 확인한 주제입니다
블록 B·C만 노출	이번 주 대화에서 눈에 띄는 주제입니다
4. 항목 카드 (공통 컴포넌트)
4.1 3요소 구조
┌──────────────────────────────────────────────┐
│ [뱃지]                                        │  ← 유형 라벨
│ 전기사업법 제7조 — 사업허가 요건               │  ← 주제 (1행, 말줄임)
│ 우리 부서 8명이 이번 주 14회 확인 · 4.7배      │  ← 근거 (1행)
│ [바로 질문하기]  [원문 열기]                   │  ← 액션
└──────────────────────────────────────────────┘
슬롯	필수	최대 길이	초과 처리
뱃지	O	6자	—
주제	O	1행	text-overflow: ellipsis
근거	O	1행	축약(8명이 14회 → 14회)
액션	O	버튼 2개	원문 없을 시 1개
4.2 금지 사항
답변 본문 발췌 노출 금지 (권한 우회 위험)
질의 원문 그대로 노출 금지 (내부 코드·개인정보 포함 가능)
전체 답변 보기 링크 금지 — 바로 질문하기로 대체함
3행 이상 확장 금지 — 카드 높이 고정
5. 뱃지 정의
뱃지	조건	배경	텍스트
추천	블록 A	--badge-personal-bg	--badge-personal-fg
급상승	지난주 ≥ 1건 AND 증가율 ≥ 2.0	--badge-trend-bg	--badge-trend-fg
신규	지난주 0건	--badge-new-bg	--badge-new-fg
많이 봄	블록 C	--badge-popular-bg	--badge-popular-fg
급상승과 신규는 상호배타 — 지난주 0건을 급상승으로 표기하지 않음
한 카드에 뱃지 1개만 노출함
6. 근거 문구 템플릿
폴백 단계	템플릿	예시
정상	우리 부서 {N}명이 이번 주 {M}회 확인 · {R}배	우리 부서 8명이 이번 주 14회 확인 · 4.7배
부서 데이터 부족	전사 {N}명이 이번 주 {M}회 확인	전사 42명이 이번 주 210회 확인
신규 주제	이번 주 새로 나타난 주제 · {M}회	이번 주 새로 나타난 주제 · 14회
관리자 큐레이션	관리자 추천	관리자 추천
부서 데이터가 없을 때 우리 부서 문구를 사용하지 않음 — 신뢰도 훼손
증가율은 소수 첫째 자리까지, 10배 초과 시 10배 이상으로 표기함
7. 액션 동작
버튼	동작	비고
바로 질문하기	주제를 질의로 변환하여 본인 권한으로 신규 대화 시작	타인 답변 재사용 금지
원문 열기	RAG 출처 문서 뷰어 이동	권한 없을 시 버튼 미노출
관심 없음	해당 주제 30일 재노출 차단	호버 시 카드 우상단 노출
8. 빈 상태·예외
상황	처리
블록 임계값 미달	블록 전체 미노출 (제목 포함)
3개 블록 모두 미달	브리핑 카드 미노출 — 빈 카드·안내문구 표시 금지
데이터 로딩 중	스켈레톤 3행, 최대 2초 후 미노출 처리
API 오류	카드 미노출, 콘솔 로그만 기록

매일 아침 오늘은 브리핑할 내용이 없습니다 카드가 남으면 사용자가 영역 자체를 무시하게 됨

9. 반응형
브레이크포인트	레이아웃
≥ 1280px	항목 카드 2열 그리드
768 ~ 1279px	1열
< 768px	1열, 액션 버튼 전폭, 근거 문구 축약형
모바일에서 근거 문구는 14회 · 4.7배 형태로 축약함
카드 좌우 여백은 --space-4 고정

뱃지 색상은 기존 플랫폼 팔레트에서 선정하며, 신규 색상 추가하지 않음
항목 카드 높이는 3요소 기준 고정값 사용 — 가변 높이 금지
11. 접근성
브리핑 카드 role="region", aria-label="아침 브리핑" 부여함
뱃지는 색상만으로 구분하지 않으며 텍스트 병기함
항목 카드 전체가 아닌 액션 버튼에만 포커스 부여함
증가율은 시각 요소(화살표) 단독 사용 금지, 텍스트 병기함
키보드 포커스 링 표시, prefers-reduced-motion 준수함
12. 데이터 바인딩 규격
필드	타입	설명
block_type	enum	personal / trending / popular
topic_id	string	주제 클러스터 ID
topic_label	string	정규화된 주제명 (질의 원문 아님)
badge	enum	recommend / trending / new / popular
evidence_scope	enum	dept / org / curated
user_count	int	고유 사용자 수
query_count	int	이번 주 질의 수
ratio	float	증가율, 신규 시 null
source_doc_id	string | null	원문 문서 ID, 권한 없을 시 null
has_source_permission	bool	원문 열기 버튼 노출 여부
서버는 임계값 통과 항목만 전달하며, 클라이언트는 필터링을 수행하지 않음
topic_label은 서버에서 정규화·마스킹 완료 후 전달함
