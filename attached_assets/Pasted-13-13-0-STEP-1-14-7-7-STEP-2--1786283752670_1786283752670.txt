13. 섹션별 산정 로직
13.0 공통 전처리 (모든 블록 선행)
STEP 1. 원본 수집
        최근 14일 대화 로그 (이번 주 7일 + 지난 주 7일)

STEP 2. 질의 제외 필터
        - 지시어 단독 (요약해줘 / 더 자세히 / 다시 설명해줘)
        - 메타 질의 (작성자가 누구야 / 몇 페이지야 / 언제 만들었어)
        - 후속턴 (세션 내 2턴 이후)
        - 3자 미만 질의

STEP 3. 주제 클러스터링
        클러스터 키 = 대상 엔티티 + 의도
          대상 엔티티 : 답변에 인용된 문서·법령·테이블 ID
          의도        : 요약 / 근거확인 / 절차 / 수치조회
        엔티티 미확정 질의 → 클러스터 제외

STEP 4. 집계 테이블 생성 (클러스터 × 기간 × 조직 단위)
        cnt_this   이번 주 질의 수
        cnt_prev   지난 주 질의 수
        usr_this   이번 주 고유 사용자 수
        cnt_dept   내 부서 이번 주 질의 수
        usr_dept   내 부서 이번 주 고유 사용자 수

정규화 함수 (공통)

norm(x) = ln(1 + x) / ln(1 + max_x)      // 0 ~ 1
  max_x : 동일 배치 내 후보 클러스터의 최댓값
  max_x = 0 이면 norm(x) = 0
13.1 블록 A. 나에게 관련
score_A = 0.5 × sim_topic
        + 0.3 × norm(cnt_dept)
        + 0.2 × recency

sim_topic : 내 최근 30일 대화 주제 벡터 ↔ 클러스터 주제 벡터 코사인 (0~1)
            내 대화 주제 벡터 = 최근 실행 대화 20건의 임베딩 평균
recency   : max(0, 1 − 클러스터_최초발생후_경과일 / 14)
항목	값
노출 임계값	score_A ≥ 0.6
정렬	score_A DESC
개수	최대 2건
후보 범위	내 부서 발생 클러스터

폴백

조건	처리
내 대화 세션 < 3건	sim_topic 산출 불가 → 블록 A 전체 미노출
부서 질의 로그 없음	cnt_dept → 전사 cnt_this 로 치환, 가중치 유지

블록 A는 개인화가 성립하지 않으면 노출하지 않음. 폴백으로 전사 인기를 채우면 블록 C와 중복됨

13.2 블록 B. 급상승 주제
증가율 ratio = cnt_this / max(cnt_prev, 1)

score_B = ln(ratio) × ln(1 + cnt_this)

노출 조건 (AND, 전부 충족)

조건	값	목적
cnt_this ≥ 10	모수 하한	3~5건 노이즈 배제
ratio ≥ 2.0	실질 증가	미미한 변동 배제
usr_this ≥ 5	고유 사용자	1인 반복 질의 배제
항목	값
정렬	score_B DESC
개수	최대 3건
후보 범위	내 부서 우선 → 미달 시 본부 → 미달 시 전사

급상승 / 신규 분기

IF cnt_prev = 0  → 뱃지 [신규],  ratio = null,  근거 문구 "이번 주 새로 나타난 주제"
ELSE             → 뱃지 [급상승], ratio 표기
score_B 는 증가율과 절대량의 곱 — 둘 중 하나만 크면 상위 진입 불가
ln(ratio) 사용으로 100배 급증이 순위를 독점하는 왜곡을 완화함
cnt_prev = 0 인 클러스터는 ratio = cnt_this 로 계산하되 뱃지만 분리함
13.3 블록 C. 많이 본 주제
score_C = 0.7 × norm(usr_this) + 0.3 × norm(cnt_this)

노출 조건 (AND)

조건	값	목적
cnt_this ≥ 5	모수 하한	—
usr_this ≥ 3	고유 사용자	소수 인원 역추적 방지
항목	값
정렬	score_C DESC
개수	최대 2건
후보 범위	내 부서 → 미달 시 본부 → 미달 시 전사
고유 사용자 수 가중이 질의 건수보다 높음 — 1인이 20회 반복한 클러스터가 1위로 오르는 왜곡 차단
폴백 단계가 바뀌면 근거 문구도 함께 전환됨 (6장 템플릿 참조)
13.4 실행 순서 및 중복 제거
① 공통 전처리 → 클러스터 집계 테이블 확정
② 블록 A 산출 → 노출 ID 집합 S_A
③ 블록 B 산출 → 후보에서 S_A 제외 → 노출 ID 집합 S_B
④ 블록 C 산출 → 후보에서 (S_A ∪ S_B) 제외 → 노출 확정
⑤ 사용자 [관심 없음] 처리 클러스터 30일 제외 (전 블록 공통)
순서 고정. A → B → C 방향으로만 제외하며 역방향 제외는 수행하지 않음
제외 후 개수 미달 시 빈 슬롯을 채우지 않음 (하위 순위로 보충하지 않음)
13.5 배치 및 캐시
항목	값
실행 주기	일 1회, 05:00
산출 범위	블록 B·C는 부서 단위 1회 산출 후 부서원 공유
개인 산출	블록 A만 사용자 단위 산출
캐시 TTL	24시간
무효화	[관심 없음] 클릭 시 해당 사용자 캐시 즉시 갱신

블록 B·C를 사용자 단위로 계산하면 동일 부서 내 결과가 같음에도 인원수만큼 연산이 반복됨. 부서 단위 1회 산출이 필수
