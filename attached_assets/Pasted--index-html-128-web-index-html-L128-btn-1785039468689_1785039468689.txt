# 나만의 비서 만들기 — 기능 구성

브라우즈 툴바의 **`+ 나만의 비서 만들기`** 버튼([index.html:128](../web/index.html#L128), `$btnNewBuilder` → `enterBuilderMode()` [app.js:1231](../web/app.js#L1231))으로 시작하는 비서 생성 흐름입니다.

**한 줄 요청 → 초안 자동 생성(1단계) → 폼 확인·수정 후 생성(2단계)** 의 2단계 구조입니다.

```
[+ 나만의 비서 만들기]
        │
        ▼
┌──────────────────────┐        ┌──────────────────────┐
│ 1단계 · 빌더 채팅      │  초안   │ 2단계 · Fast-fill 폼   │
│ 한 줄 답변            │  JSON  │ 8+ 항목 확인·수정      │
│ → 초안 JSON 자동 생성  │ ─────▶ │ → [만들기]/[임시저장]   │
└──────────────────────┘        └──────────────────────┘
```

---

## 1단계 · 빌더 채팅 (한 줄 요청)

`state.mode = "builder"` 상태의 대화 화면. 사용자가 만들고 싶은 비서를 **한 줄로** 말하면 LLM이 편집 가능한 **비서 초안 JSON 한 벌**을 생성합니다.

- 시스템 프롬프트: [builder_system_prompt.md](../builder_system_prompt.md)
- 첫 인사(`BUILDER_GREETING`, [app.js:6](../web/app.js#L6)):
  > 안녕하세요! 나만의 비서를 만드는 것을 도와드릴게요.
  > 예를 들어 "우리 회사 매뉴얼을 참고해 답변해주는 비서"나 "PPT 문구를 영어로 바꿔주는 번역 비서"처럼 한 줄로 말씀해 주세요.
- API: `POST /api/builder/chat` (스트리밍) — [app.js:2536](../web/app.js#L2536)
- 첨부 버튼은 숨김 (한 줄 답변 흐름이라 부적합) — [app.js:1080-1081](../web/app.js#L1080-L1081)

### 동작 규칙 (빌더 LLM)

- 첫 턴에서만 인사말 출력, JSON은 출력하지 않음.
- 두 번째 턴부터는 **부연 설명 없이 JSON 한 벌만** (코드펜스 ` ```json ` 만 허용).
- 부족한 정보는 되묻지 않고 **합리적 기본값으로 추측해 채움** (사용자가 폼에서 수정).
- 값은 한국어 존댓말. 폼 수정 후 자연어 지시("좀 더 친절한 톤으로")를 보내면 **8개 필드 전체를 다시 채운 새 JSON** 재출력.

### 초안 JSON 8개 필드

응답에서 ` ```json ``` ` 블록을 `extractDraft()`가 파싱([app.js:2600-2618](../web/app.js#L2600-L2618)) → 성공 시 채팅 버블 제거하고 `enterFormView(draft)`로 **자동 전환**. 파싱 실패 시 텍스트를 그대로 노출하고 재시도 유도.

스키마: [assistant_draft.schema.json](../assistant_draft.schema.json)

| # | 필드 | 타입 | 설명 / 제약 |
|---|---|---|---|
| 1 | `name` | string | 비서 이름 (1~20자, 필수) |
| 2 | `description` | string | 한 문장 설명 (≤80자, 한글 40자 이내 권장) |
| 3 | `instructions` | string | 역할/전문성/응답 방식/불확실 시 처리 지침 (멀티라인, 5~12줄) |
| 4 | `prohibitions` | string[] | 금지 사항 (보통 3~5개, 최대 20) |
| 5 | `conversation_starters` | string[] | 대화 스타터 질문 (3~4개 권장, 최대 8) |
| 6 | `knowledge_files` | string[] | 참고 지식 파일명 (없으면 빈 배열, 최대 20) |
| 7 | `first_message` | string | 비서를 처음 열 때 자동 인사말 (비어도 됨) |
| 8 | `use_foundation_model` | boolean | 파운데이션 모델 일반 지식 병용 여부 (보통 true, "업로드 파일만" 강제 시 false) |

## 2단계 · Fast-fill 폼 (`#form-view`)

초안을 폼에 채워(`fillFormFromDraft()` [app.js:2643](../web/app.js#L2643)) 사용자가 확인·수정 후 생성합니다. 헤더/버튼은 모드에 따라 달라집니다 — 생성은 `[만들기]`, 수정은 `[저장]` ([app.js:2625-2635](../web/app.js#L2625-L2635)).

> 폼 진입 경로는 두 가지: **1단계 초안 전환**(create) / **기존 비서 수정**(edit, `enterEditMode()` [app.js:2639](../web/app.js#L2639)).

## 액션

폼 하단 3버튼 [index.html:271-274](../web/index.html#L271-L274) · 핸들러 `handleFormSubmit()` [app.js:2971](../web/app.js#L2971)

| 버튼 | 동작 | 검증 | 결과 |
|---|---|---|---|
| **취소** `#form-cancel` | 폼 종료 | — | 브라우즈로 복귀 |
| **임시저장** `#form-draft-save` | `handleFormSubmit(true)` — `is_draft=true` | 이름만 필수 (지침 미완성 허용, 심의 미신청) | `POST/PUT /api/assistants` → '나의 비서'에 **임시저장 배지**로 복귀 |
| **만들기 / 저장** `#form-submit` | `handleFormSubmit(false)` | 이름(≤20자)·지침 필수 | 비서 생성/수정 |

### 만들기 시 처리 흐름

1. `collectDraftFromForm()`으로 전 항목 수집 → `POST /api/assistants`(생성) 또는 `PUT /api/assistants/{id}`(수정) — [app.js:2992-2993](../web/app.js#L2992-L2993).
2. **심의 신청**(`#form-request-review` 체크) 시 이어서 `POST /api/assistants/{id}/submit-official` 호출 → `official_pending` 전환 — [app.js:3013-3025](../web/app.js#L3013-L3025).
3. 결과 상태에 따라 분기:
   - **심의로 잠긴 경우**(`isChatLocked`): 채팅 대신 '나의 비서' 목록으로 복귀 + 안내 alert.
     - 신규 → `승인 대기`, 기존 공식 수정 → `버전 갱신중`.
   - 그 외: 생성된 비서로 바로 진입/이용.

> 생성 후 상태 배지·잠금 규칙은 [비서-상세-모달-구성.md](비서-상세-모달-구성.md) §2, §9 참조.
